Une commande d'installation est ce que ce livre contient de plus périssable : c'est pour cette raison qu'elle vit ici et non sur le papier. Les commandes ci-dessous ont été relevées à la source d'Anthropic à la date indiquée. Aucune des douze tâches du livre n'en a besoin : vous n'êtes ici que si votre organisation vous l'impose, si vous travaillez sous Linux, ou si vous payez à la consommation. Dernière vérification à la source : 30/10/2026.

Installer Claude Code en ligne de commande

Chapitre 4, section 4.8, et le tableau de dépannage de la section 4.9.

Le livre vous installe l'application de bureau, et c'est la bonne voie : aucun des douze cas n'a besoin du terminal. Voici tout de même la marche à suivre en ligne de commande, système par système, pour les organisations qui l'imposent.

La voie recommandée est l'installeur fourni par Anthropic. Elle ne demande ni Node.js ni droits d'administrateur : c'est ce que promet la section 4.9 du livre, et c'est toujours vrai. Ouvrez un terminal et tapez la ligne qui correspond à votre système.

🍎 macOS, Linux et WSL

curl -fsSL https://claude.ai/install.sh | bash

🪟 Windows PowerShell

irm https://claude.ai/install.ps1 | iex

🪟 Windows, invite de commandes (CMD)

curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd

Sous Windows, vous reconnaissez PowerShell à son invite, qui commence par PS C:\ ; l'invite de commandes affiche C:\ sans le PS. Deux messages lèvent le doute si vous vous êtes trompé de fenêtre : « The token '&&' is not a valid statement separator » signifie que vous êtes dans PowerShell, et « 'irm' is not recognized as an internal or external command » que vous êtes dans l'invite de commandes.

L'installation n'affiche aucune progression pendant le téléchargement : c'est normal, laissez-la finir. Ouvrez ensuite une NOUVELLE fenêtre de terminal, puis tapez claude --version. Une installation qui marche répond par un numéro de version. Si le terminal répond que claude est introuvable ou n'est pas reconnu, l'installation a réussi mais son dossier n'est pas encore déclaré dans le chemin de recherche de votre système : fermez toutes vos fenêtres de terminal et rouvrez-en une, ce qui suffit dans la plupart des cas.

⚠️ La voie npm est une voie de repli, pas la voie normale. Si votre organisation l'impose, la commande est npm install -g @anthropic-ai/claude-code, et elle exige Node.js installé au préalable. Ne la lancez jamais avec sudo : Claude Code se met à jour tout seul sans sudo, et une installation faite en administrateur ferait échouer chacune de ses mises à jour. Si elle échoue sur un message EACCES, revenez à l'installeur ci-dessus plutôt que de recommencer en administrateur.

Un dernier point, sous Windows seulement : Anthropic recommande d'installer Git pour Windows (git-scm.com), qui donne à Claude Code un interpréteur de commandes plus complet. Sans lui, il se rabat sur PowerShell et fonctionne tout de même. Cette recommandation ne vaut que pour la ligne de commande : l'application de bureau du livre ne demande rien de tel, et la section 4.9 le dit.

Installer l'application de bureau sous Linux

Chapitre 4, section 4.2.

Le livre décrit les écrans de Windows et de Mac, qui sont les mêmes. L'application existe aussi sous Linux, en version bêta, et vous y retrouvez les mêmes onglets et le même Claude Code.

Deux conditions : une distribution Linux dérivée de Debian, c'est-à-dire Ubuntu 22.04 ou plus récent, ou Debian 12 ou plus récent ; et un processeur x86_64 ou arm64. Les autres distributions dérivées de Debian peuvent fonctionner sans être testées officiellement. Si vous êtes sous Fedora ou Arch, il n'y a pas d'application de bureau : reprenez la section précédente, qui installe la version en ligne de commande.

L'installation passe par le dépôt de paquets d'Anthropic, ce qui vous vaut les mises à jour automatiquement, avec celles de votre système. Ouvrez un terminal. Si curl ou gpg vous manquent, installez-les d'abord :

1. les deux outils nécessaires

sudo apt install curl gnupg

2. la clé de signature d'Anthropic

sudo curl -fsSLo /usr/share/keyrings/claude-desktop-archive-keyring.asc https://downloads.claude.ai/claude-desktop/key.asc

Cette commande n'affiche rien quand elle réussit. Vérifiez la clé avant d'aller plus loin, car une clé absente ou fausse fera échouer l'étape suivante sur un message NO_PUBKEY :

3. vérifier l'empreinte de la clé

gpg --show-keys /usr/share/keyrings/claude-desktop-archive-keyring.asc

L'empreinte affichée doit être exactement 31DDDE24DDFAB679F42D7BD2BAA929FF1A7ECACE. Si elle diffère, ou si gpg annonce qu'il ne trouve aucune donnée OpenPGP valide, le téléchargement a échoué : ne poursuivez pas, recommencez l'étape précédente.

4. déclarer le dépôt

echo "deb [arch=amd64,arm64 signed-by=/usr/share/keyrings/claude-desktop-archive-keyring.asc] https://downloads.claude.ai/claude-desktop/apt/stable stable main" | sudo tee /etc/apt/sources.list.d/claude-desktop.list

5. installer l'application

sudo apt update && sudo apt install claude-desktop

Lancez ensuite Claude depuis le menu de votre environnement de bureau, ou par la commande claude-desktop, et connectez-vous avec votre compte. La connexion se fait comme sous macOS et Windows, par votre abonnement ou par l'authentification unique de votre organisation.

📝 Un seul morceau de l'application demande davantage sous Linux. L'espace de travail destiné aux tâches longues y tourne dans une machine virtuelle, ce qui suppose la virtualisation matérielle activée dans les réglages de votre machine, et votre compte ajouté au groupe kvm par sudo usermod -aG kvm $USER, suivi d'une déconnexion et d'une reconnexion. Les douze cas du livre n'en ont pas besoin.

Créer votre clé API, et la conserver

Chapitre 4, section 4.1, et Chapitre 6, section 6.3.

Rappel avant de commencer : aucune des douze tâches de ce livre n'exige de clé. Pour un usage régulier, l'abonnement revient moins cher et vous dispense de surveiller votre consommation. Vous n'avez besoin d'une clé que si vous payez à la consommation, le plus souvent parce que votre service informatique l'a préféré à un abonnement par utilisateur.

Pour créer votre clé, ouvrez platform.claude.com/settings/keys, la page « Clés API » de la console Anthropic, et cliquez sur « Create key ». Trois réglages vous sont demandés. Le nom, qui ne sert qu'à vous y retrouver. L'expiration, à choisir parmi trois heures, un jour, sept jours, trente jours, une durée de votre choix, ou « Never » pour une clé sans échéance. Et « Linked account », que vous mettez sur vous-même pour une clé personnelle, ou sur un compte de service pour une clé que plusieurs personnes utiliseront.

Choisissez une expiration plutôt que « Never », même courte. C'est le seul réglage qui limite les dégâts d'une clé qui s'échappe, et il ne se modifie plus après coup : une clé créée sans échéance le reste. Si votre organisation impose une durée maximale, la console vous empêchera de la dépasser et « Never » n'y sera pas proposé.

Rangez la clé dans un gestionnaire de mots de passe dès sa création, et nulle part ailleurs : ni dans un document, ni dans un courriel, ni dans un fichier posé sur votre bureau. La règle 1 de la section 6.3 vaut ici sans exception : ne dictez jamais votre clé à Claude Code, dans aucune conversation. Elle se tape dans le terminal, ou se range dans une variable d'environnement, et c'est tout.

Si vous soupçonnez qu'une clé a fuité, retournez sur la même page. « Disable » la suspend et se défait, « Re-enable » la remet en service. « Delete » est définitif. Dans le doute, désactivez d'abord : vous verrez tout de suite ce qui cesse de fonctionner, et vous pourrez revenir en arrière.

Les adresses officielles qui permettent de vérifier ces procédures par vous-même vivent sur la page Sources officielles.
