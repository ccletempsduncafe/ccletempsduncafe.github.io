Le Chapitre 19 vous a laissé avec un fichier instruction.md qui donne le bon résultat. Il vous reste pourtant un geste à faire chaque mois : ouvrir le dossier, retrouver le fichier, et demander à Claude Code de le lire. Une compétence supprime ce geste. Vous formulez votre demande comme vous la formuleriez à un collègue, et la procédure s'applique d'elle-même.

Comptez vingt minutes le premier jour, puis cinq minutes le lendemain pour le contrôle. Vous n'avez rien à rédiger : c'est Claude Code qui écrit le fichier, à partir de celui que vous avez déjà.

Ce qu'est une compétence

Une compétence est un dossier qui porte un fichier nommé SKILL.md. Ce fichier commence par un en-tête de deux lignes : un nom, et une description qui dit ce que la compétence fait et quand l'utiliser. Sous cet en-tête vient le corps du fichier, c'est-à-dire votre procédure, celle que instruction.md contient déjà. Claude Code découvre les compétences déposées dans ses dossiers et les utilise automatiquement lorsqu'elles correspondent à votre demande.

La lecture se fait en deux temps, et c'est ce qui rend la chose économique. Au démarrage d'une session, Claude Code ne lit que l'en-tête, le nom et la description, ce qu'Anthropic chiffre à une centaine de tokens par compétence. Le corps du fichier, lui, n'est lu que le jour où votre demande correspond à la description. Deux conséquences pratiques : vous pouvez en garder plusieurs sans alourdir vos sessions, et c'est la description qui décide du déclenchement automatique.

Ce qui la distingue du fichier de contexte

Le fichier CLAUDE.md du Chapitre 20 est lu au début de chaque session, quel que soit le travail du jour. Une compétence n'est consultée que le jour où le cas se présente. Cette différence de moment commande ce que vous mettez dans l'un et dans l'autre.

Le partage se fait par une question simple. Si l'information doit rester vraie pour tout ce que vous faites, votre métier, vos clients, vos conventions de rédaction, elle va dans CLAUDE.md. Si elle ne sert que le jour du rapport mensuel, elle va dans une compétence. Les deux coexistent sans se gêner : le fichier de contexte dit qui vous êtes, la compétence dit comment se fait une tâche précise.

La demande à formuler

Ouvrez Claude Code sur le dossier où vous ferez ce travail chaque mois, celui qui contient vos sources. Si votre instruction.md est resté dans le dossier d'essai du Chapitre 19, copiez-le ici d'abord : c'est ce dossier de travail, et lui seul, que vous ouvrirez désormais. Puis collez la demande ci-dessous. Le passage entre crochets est une case à remplir : remplacez-le entièrement, crochets compris.

Voici le fichier instruction.md que j'ai mis au point et qui donne
maintenant le bon résultat. Transforme-le en compétence : crée le dossier
et le fichier SKILL.md qui va avec, en reprenant ma procédure telle quelle,
sans la réécrire ni la résumer.

L'en-tête du fichier doit porter un nom en minuscules et tirets, et une
description qui dise à la fois ce que fait la compétence et dans quels cas
l'utiliser. Rédige cette description avec les mots que j'emploie moi-même
pour demander ce travail, à savoir : [la phrase avec laquelle vous demandez
cette tâche, telle que vous la diriez à un collègue].

Dépose la compétence dans le sous-dossier .claude/skills de ce dossier-ci,
pour qu'elle serve quand je travaille ici. Montre-moi le contenu du fichier
avant de l'écrire, et dis-moi ensuite le chemin exact où tu l'as écrit.

Un mot sur ce sous-dossier .claude/skills, puisque le prompt le nomme. Anthropic documente deux endroits où une compétence peut vivre dans Claude Code : un dossier personnel, ~/.claude/skills, rangé dans votre compte utilisateur et loin de vos documents, et un dossier de projet, .claude/skills, qui vit à l'intérieur du dossier de travail lui-même. La documentation nomme le premier « personnel » et le second « basé sur le projet », mais elle ne dit pas depuis quels dossiers de travail chacun se déclenche. Le prompt demande donc le dossier de projet, dont l'emplacement ne laisse aucun doute : la compétence est rangée dans le dossier même où vous travaillez. C'est un dossier technique, que vous n'aurez jamais à ouvrir vous-même.

Claude Code vous montre le fichier avant de l'écrire, puis vous donne le chemin où il l'a écrit. Notez ce chemin quelque part : il ne servira que le jour où quelque chose ne se déclenche pas. Deux points seulement vous concernent à cet instant. Le premier est le corps du fichier : ce doit être votre procédure, avec vos phrases. Si elle a été réécrite ou raccourcie, demandez qu'elle soit remise telle quelle, car c'est cette rédaction-là que vous avez éprouvée au Chapitre 19.

Le second est la description. Relisez-la à voix haute et demandez-vous si elle emploie vos mots. Une description écrite dans le vocabulaire de la documentation ne se déclenchera pas sur la phrase que vous tapez le lundi matin. Le nom, lui, obéit à trois contraintes qu'Anthropic impose : minuscules, chiffres et tirets uniquement, soixante-quatre caractères au plus, et ni « claude » ni « anthropic » dedans. Claude Code les respecte, mais vous saurez pourquoi si un nom vous est refusé.

Vérifier le lendemain qu'elle se déclenche seule

Le jour où vous fabriquez la compétence, elle fonctionnera : la conversation en cours contient déjà tout ce qu'il faut, et vous ne testez rien. Le contrôle qui compte se fait à la session suivante, dans quatre gestes.

  1. Ouvrez Claude Code sur votre dossier de travail, celui qui contient vos sources du mois et où vous avez fabriqué la compétence. Ce n'est pas le sous-dossier technique où le fichier a été rangé : celui-là, vous ne l'ouvrez jamais.
  2. Formulez votre demande avec vos mots, sans nommer le fichier instruction.md ni la compétence.
  3. Avant de le laisser produire quoi que ce soit, demandez-lui : « quelles instructions appliques-tu pour ce travail ? » S'il vous répond en citant votre compétence, elle s'est déclenchée toute seule.
  4. Laissez-le travailler, puis comparez le résultat au livrable du mois précédent, comme vous l'aviez fait au Chapitre 19. C'est la seule preuve qui compte vraiment.

Si la réponse ne cite pas votre compétence, vérifiez d'abord le fichier avant d'accuser la description. Demandez-le en une phrase : « où as-tu déposé la compétence, et est-elle disponible depuis ce dossier ? » Un fichier écrit ailleurs que dans le .claude/skills de ce dossier, ou un dossier renommé depuis, suffit à expliquer le silence. Faites-la redéposer ici et reprenez l'essai.

Si le fichier est bien là où il doit être, c'est alors la description qui est en cause, et non votre procédure. Rouvrez SKILL.md, remplacez la description par la phrase exacte que vous venez de taper, et refaites l'essai à la session suivante. En attendant, vous ne perdez rien : votre fichier instruction.md n'a pas bougé, et vous le désignez comme au Chapitre 19.

⚠️ N'installez que ce que vous avez écrit

Une compétence est une instruction que Claude Code suit. Celle qui vient d'un inconnu peut lui demander tout autre chose que ce que son titre annonce. Anthropic recommande de n'utiliser que les compétences que vous avez créées vous-même ou qui viennent d'Anthropic. Traitez leur installation comme celle d'un logiciel.

📝 Une compétence reste là où elle est écrite

Celle que vous fabriquez dans Claude Code vit dans vos fichiers. Anthropic écrit que les compétences personnelles ne se synchronisent pas d'une surface à l'autre : n'attendez donc pas de retrouver la vôtre sur claude.ai ou dans l'interface de programmation.
