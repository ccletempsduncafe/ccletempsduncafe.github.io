Le feuillet à donner à votre équipe

Claude Code dans notre équipe : la page à lire avant de commencer

Cet outil s'utilise depuis votre poste. Les fichiers que vous lui donnez sont transmis aux serveurs d'Anthropic pour y être traités, comme lorsque vous déposez une pièce jointe sur un service en ligne. C'est la seule raison d'être des cinq règles qui suivent. Il lit les fichiers du dossier depuis lequel vous le lancez, produit des documents et ne remplace aucun des outils que vous utilisez déjà. Cinq règles suffisent, elles sont détaillées au Chapitre 23 du livre.

Première règle : aucun mot de passe, aucune clé d'accès, aucun identifiant ne se tape dans une conversation. Si vous devez configurer un accès, il se configure dans un fichier de configuration, jamais dans l'échange.

Deuxième règle : avant de transmettre des données personnelles, vérifiez nos obligations. Cela vaut pour les clients, mais aussi pour les collègues nommés dans un dossier d'intégration, pour les candidats d'un tri de candidatures et pour les tiers. Dans le doute, remplacez les noms par « Client A », « Client B » avant de transmettre le fichier : le résultat est le même.

Troisième règle, celle qui tranche en dix secondes : est-ce que j'enverrais ce document par email à un prestataire de confiance ? Si oui, vous pouvez le donner à Claude Code. Si non, ne le faites pas.

Quatrième règle : ne lancez pas un agent autonome sur des fichiers que vous ne pouvez pas vous permettre de perdre. Copiez votre dossier de projet avant, cela prend cinq secondes.

Cinquième règle : tout document destiné à l'extérieur est relu et validé par vous avant envoi. L'outil produit un premier jet, vous portez la responsabilité.

Trois interdits s'ajoutent dès qu'un agent travaille seul : il n'envoie jamais de communication à l'extérieur sans votre validation, il ne modifie jamais de données dans un système de production, il ne supprime jamais un fichier source. Écrivez ces règles dans votre fichier CLAUDE.md (Chapitre 20) et répétez-les dans chaque objectif d'agent.

Enfin, verrouillez votre session quand vous quittez votre poste, même cinq minutes. Une session ouverte est une session utilisable par quelqu'un d'autre.

En cas de doute sur un cas précis, la question se pose avant, pas après.

La page à présenter à votre responsable informatique

Claude Code s'exécute localement sur les postes des utilisateurs. Il n'y a pas d'installation côté infrastructure de l'organisation. Les données transmises passent par une connexion HTTPS chiffrée vers les serveurs Anthropic, comme n'importe quel service cloud en ligne.

Anthropic propose un accord de traitement de données (DPA) compatible RGPD pour les organisations soumises à cette réglementation. Les formules Team et Enterprise, destinées aux organisations, incluent des garanties supplémentaires sur la confidentialité.

Si vos collaborateurs travaillent avec un abonnement individuel, Free, Pro ou Max, l'exclusion de l'entraînement des modèles n'est pas acquise d'avance : leurs échanges peuvent y servir, sauf s'ils s'y opposent dans les réglages de confidentialité de leur compte. Ce réglage se vérifie une fois, en cinq minutes, avant la première session de travail sur des données professionnelles (Chapitre 23, section 23.1, « Ce que Claude Code fait de vos données »).

L'usage est individuel et traçable : chaque utilisateur travaille avec son propre compte, un abonnement Claude Pro ou Claude Max dans la plupart des cas, ou une clé API à la consommation si votre organisation retient cette formule. Chacun a son propre historique d'utilisation, et il n'y a pas de mélange entre utilisateurs. Ce que l'outil retient de vous reste sur le poste : le fichier de contexte que l'utilisateur écrit lui-même et les notes de la mémoire automatique sont des fichiers locaux, lisibles et effaçables par lui (Chapitre 20).

Les cinq règles de sécurité du Chapitre 23 s'appliquent et sont simples à communiquer à l'équipe.
